# 独立远程桌面产品路线

2026-09-29 用户确认：最终面向其他用户提供接近 AnyDesk 的独立安装和连接体验。该目标扩大长期产品范围；当前先完成 Mac 控制 Windows 的基础链路。

## 最终用户体验

两端安装并启动应用，Windows 展示设备标识和连接状态，Mac 输入设备标识或邀请信息发起连接；Windows 明确确认访问，用户可随时停止。普通用户无需配置 SSH、复制终端命令或自行配置第三方组网工具。设备信任、授权撤销、网络失败、升级和卸载都有图形界面流程。

这是最终目标，不是当前产品已具备的能力，也不承诺功能范围与 AnyDesk 完全相同。

## 实施顺序

1. **现有基础链路**：完成 P1 画质与稳定性；完成 P2 输入预览、认证 TLS mock、真实键鼠和本机停止验收。开发阶段继续使用 Tailscale。
2. **可供小范围测试的安装版**：图形配对、可信设备管理、认证失败退避、断线重连、诊断导出、签名、公证、版本升级与干净机器安装/卸载。验证 4 小时耐久；H.264 按原 P4 单独安排。
3. **独立连接架构**：设计设备注册/身份、短期邀请、信令、直连探测与中继回退；先完成威胁模型、连接协议和服务成本估算，再实现服务。账户是否必需、有人值守与无人值守模式分别设计。
4. **独立连接实现与试用**：客户端显示直连/中继状态，处理服务不可达与连接失败；跨运营商/热点/受限网络验证。服务只承担寻址与转发，端到端加密与设备认证保持独立。
5. **对外发布**：代码签名/公证、可信更新与失败回退、最小诊断数据、明确隐私说明、滥用处理、依赖许可证核查、服务运维和支持流程；从有限用户试用开始。

## 当前范围

当前推进 Mac 输入模拟链路（采集、队列、TLS 适配），下一步优先完成 Mac 验证检查点，不创建账户服务、设备目录、穿透或中继，不部署服务器、不购买资源、不修改防火墙。不将“最终独立体验”解释成现在开放公网输入端口。

现有 Tailscale 寻址与应用 TLS/HMAC 可继续支撑早期验证；后续独立网络发现应与认证/视频/输入协议解耦。开发用 SSH 仅为诊断通道，不作为最终用户依赖。

2026-10-02 集成决策：MVP 不将 Tailscale 后台或 macOS 系统扩展重打包进本项目安装器。短期集成定义为 GUI 检测官方客户端的安装、登录和在线状态，并提供明确的安装或登录入口。完整内嵌需单独评估官方 Go tsnet 边车、每个应用独立节点身份、登录/注销、状态保护、升级、平台权限及许可证；该工作属于独立连接架构，不与当前安装包收尾混合。

下一任务按 [P2 输入交接](P2_INPUT_HANDOFF.md) 继续；当前阻塞和实际测试以 [HANDOFF](HANDOFF.md) 顶部为准。
