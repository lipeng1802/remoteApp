# 测试计划

## 1. 测试原则

- 协议、坐标和状态机优先自动化。
- 屏幕采集、硬件编码、真实输入和跨外网连接必须在实际 Mac/Windows 设备上验证。
- 每个阶段都保留可运行垂直切片，不能等全部模块完成后再联调。
- 自动测试不得向真实桌面注入不可控输入；输入模块必须支持 mock。

## 2. 测试环境

### macOS 控制端

- 当前设备：Intel x86_64。
- 当前系统：macOS 13.7.6。
- 当前检测到 Swift 5.8.1 和 Command Line Tools。
- 尚未检测到完整 Xcode，需要在 P0 确认。

### Windows 被控端

开始编码前记录：

- Windows 版本和 OS Build。
- CPU、GPU、内存。
- 显示器分辨率、DPI 缩放和刷新率。
- .NET 8 SDK 版本。
- Tailscale 版本及设备名。

不要把真实 IP、认证密钥或设备凭据写入仓库。

## 3. 自动化测试

### 3.1 协议单元测试

Mac 和 Windows 两端都要覆盖：

- 每类消息编码后可正确解码。
- Swift 与 C# 读取同一份 `protocol/testdata` 得到一致结果。
- 不完整头部、不完整载荷和粘包/拆包。
- 未知消息类型和不支持的协议版本。
- 零长度、最大合法长度和超长载荷。
- 非法枚举、整数溢出和错误字节序。
- 视频帧损坏后不会导致后续控制消息失去边界。

### 3.2 状态机测试

- 未连接 → 连接中 → 认证中 → 已连接 → 断开。
- 认证前收到视频或输入消息时拒绝处理。
- 心跳超时进入重连状态。
- 用户主动断开时不自动重连。
- 网络失败重连采用指数退避并有最大间隔。
- 重连成功后重新协商屏幕信息和关键帧。

### 3.3 坐标测试

- 相同宽高比。
- Mac 窗口与远程屏幕宽高比不同。
- 画面 letterbox 上下或左右留黑。
- Windows 100%、125%、150%、200% DPI。
- 画布四角、中心和边界外点击。
- 归一化坐标始终限制在合法范围。

### 3.4 视频管线测试

- 生产者速度高于消费者时只保留最新帧。
- 分辨率改变时重建解码器/画布。
- H.264 在缺失非关键帧时等待或请求关键帧。
- 无效 JPEG/H.264 数据返回可诊断错误而不崩溃。
- 帧时间戳保持单调，统计值不会溢出。

### 3.5 安全测试

- 错误密码或错误认证响应被拒绝。
- 重放旧认证响应失败。
- 多次失败触发延迟或临时锁定。
- 证书指纹改变时 Mac 明确阻止自动连接。
- 日志不包含密码、认证密钥、屏幕内容或完整键盘输入。
- 超大消息和随机畸形消息不能导致内存无限分配。

## 4. 跨设备集成测试

### IT-01 基础连接

1. 两台设备登录同一 Tailscale 网络。
2. 启动 Windows Agent。
3. Mac 使用设备名连接。

期望：完成认证，显示主显示器，UI 状态正确。

### IT-02 不同网络连接

1. Windows 使用家庭宽带。
2. Mac 使用手机热点或另一网络。
3. 建立远程会话。

期望：无需端口转发即可连接；记录连接是 direct 还是 relay，但不记录地址。

### IT-03 鼠标控制

期望：移动、单击、双击、右击、拖拽和滚轮均正确，画面缩放不会造成明显坐标偏移。

### IT-04 键盘控制

在 Windows 记事本中测试字母、数字、空格、退格、方向键、Shift、Ctrl 组合键和中英文输入法基本切换。

期望：按下和释放配对；断开后 Windows 不出现卡住的修饰键。

### IT-05 网络中断

会话中关闭 Mac Wi-Fi 15 秒后恢复。

期望：UI 进入重连状态，恢复后重新认证并继续显示；不会重放断网期间的旧输入。

### IT-06 Agent 重启

期望：Mac 检测断开；Agent 重启后能重新连接，旧会话令牌不被错误复用。

### IT-07 本地终止

Windows 用户点击“断开远程控制”。

期望：连接立即关闭，Mac 显示原因，未经 Windows 允许不会静默恢复本次会话。

### IT-08 并发连接

第二个控制端尝试连接已被控制的 Agent。

期望：MVP 明确拒绝第二个会话，不允许两个控制端同时输入。

## 5. 性能测试

每次测试记录分辨率、FPS、码率、CPU、内存、连接类型和往返延迟。

| 指标 | MVP 目标 |
|---|---:|
| 分辨率 | 最低 1280×720 |
| 帧率 | 15 FPS，理想 30 FPS |
| 交互延迟 | 正常网络下 P95 小于 200 ms |
| 建立连接 | P95 小于 10 秒 |
| 断网恢复 | 网络恢复后 15 秒内 |
| 连续运行 | 4 小时无崩溃 |
| 帧队列 | 不超过实现约定的小常数 |

JPEG 阶段不以带宽作为最终验收项，但要记录数据作为 H.264 优化基线。

## 6. 兼容性矩阵

首个 MVP 至少覆盖：

| 维度 | 组合 |
|---|---|
| Mac | 当前 Intel Mac、macOS 13.7.6 |
| Windows | 实际目标 Windows 电脑 |
| Windows DPI | 100%、125%、150%（设备支持范围内） |
| 分辨率 | 1920×1080，另选一个实际分辨率 |
| 网络 | 同一局域网、不同外网、Tailscale relay（若可复现） |
| 窗口 | 普通窗口、Mac 全屏 |

## 7. 发布前回归清单

- 两端干净构建。
- 全部单元测试通过。
- `protocol/testdata` 双端通过。
- IT-01 至 IT-08 完成并记录结果。
- 4 小时耐久测试通过。
- 安装包在非开发环境启动。
- 未提交密钥、证书私钥、IP、日志或屏幕截图。
- Agent 只监听预期接口和端口。
- Windows 防火墙没有开放公网入站规则。
- macOS 保存的凭据位于 Keychain。

## 8. 缺陷等级

- **P0**：未授权访问、凭据泄漏、任意代码执行或系统损坏；停止发布。
- **P1**：频繁崩溃、无法连接、输入失控、持续黑屏；停止发布。
- **P2**：部分按键、缩放、重连或性能问题；评估后修复。
- **P3**：文案、布局和轻微体验问题；可排入后续。
